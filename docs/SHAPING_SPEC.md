# Myanmar shaping specification

This is the technical specification for the shaping model that
`pipeline/json_to_ufo.py` generates into every built font, and that
`pipeline/validate_spec.py` measures fonts against. It covers the engine
parameters, the glyph classes, the GPOS anchor system with its exact
placement rules, the GSUB rule set in application order, language
handling, and the collision-detection protocol. Background reading:
[DESIGN.md](DESIGN.md) explains *why* the model looks like this;
[TESTING.md](TESTING.md) covers the practical proof-sheet workflow.

Everything here is generated from the drawing — the studio has no
settings for any of it. Where a constant appears, it lives in
`json_to_ufo.py` and is mirrored in `web/js/anchors.js` (the studio shows
the same anchors it will build with). All calibration values were
**measured against SIL Padauk**, the reference implementation for Myanmar
shaping, not asserted from theory; the measurement is quoted next to each
value.

## 1. Engine parameters

| Parameter | Value |
| :--- | :--- |
| Units per em | 1000 |
| Baseline | y = 0 |
| Body height (letter top) | 550 |
| Design ascender | +900 |
| Wrap band (ြ ဩ ဪ ink ceiling) | +935 — measured on Padauk, whose wraps top at 932–933 |
| Design descender | −600 |
| Clipping box (usWinAscent/Descent) | +1100 / −750 |
| Attachment | GPOS `mark` + `mkmk`, generated by ufo2ft's MarkFeatureWriter from anchors |
| Minimum mark separation | 50 units (see §6) |
| Script tags | `mym2` (current), `DFLT` (fallback) — never the legacy `mymr`, which selects HarfBuzz's non-reordering Zawgyi shaper |

The design band ±900/−600 is the *drawing* guideline for everything
except the wrap class: the medial-ra hook must rise around the vowel
ring it wraps, so ြ (all variants) and the wrap-sweep letters ဩ ဪ get
the 935 band instead — Padauk's own wraps top at 932–933. The hard
verification limit everywhere is the clipping box.

## 2. Glyph classes

Classification is by name set first, Unicode category (`Mn`) for anything
outside the curated sets, so the extension blocks (Shan, Mon, S'gaw
Karen, Ext-A/B) need no hand-kept tables.

| Class | Members | GDEF | Advance |
| :--- | :--- | :--- | :--- |
| Bases | 33 consonants + ဿ + independent vowels + digits + `.alt` side-form bases | base | ink width + sidebearing |
| Top marks | ိ ီ ဲ ံ ် kinzi ိံ-ligature | mark | 0 |
| Bottom marks | ု ူ ့ ွ ှ, the traced fused pairs `ွ.ha` (+`.small`) `ှ.u` `ှ.uu` (Padauk uni103D103E / uni103E102F / uni103E1030 — one drawn hook where chaining showed two marks), plus synthesized `.small` copies and the in-wrap `u.wrapstroke` bar | mark | 0 |
| Stack marks | all `.sub` subjoined forms **drawn below the baseline** | mark | 0 |
| Side stacks | `.sub` forms drawn at body height (e.g. ဈ) | base | small positive |
| Spacing signs | ာ ါ း ေ + the tall `u/uu-myanmar.alt` strokes | base | ink width |
| Wrap signs | ြ narrow/wide/tall/tall.wide plus their fused `+u` (uni103C102F: retracted sweep, u bar in the opening) and `+wa` (uni103C103D: the wa nested inside the sweep) sets | base | ~30 % of ink width |
| Medial ya | ျ (+ `.beforewa` variant and the traced fused ligatures `.wa` ကျွ / `.ha` လျှ / `.waha` ကျွှ — one woven drawing where overlaying the parts crossed strokes) | base | small positive |

Three classifications are load-bearing and easy to get wrong:

* **ြ must be GDEF *base*.** HarfBuzz zeroes the advance of GDEF marks,
  and the wrap's small positive advance is exactly what moves the base
  inside the wrap. (Padauk itself uses class 3 and gets away with it;
  this pipeline's GPOS does not.)
* **A `.sub` drawn at full body height is a base, not a mark.** Padauk
  stacks ဇ္ဈ by placing a spacing-width ဈ *beside* the base
  (`uni1008.med`, advance 154). Decided by measurement (`y_max > 0`), so
  a font that draws a small subjoined ဈ still gets the below treatment.
* **The long `u/uu.alt` stack vowels are spacing glyphs.** They are
  body-height forms that stand to the right of a stacked cluster
  (Padauk's spacing `uni1030`, advance 288). Hung from the stack's bottom
  anchor as marks, စက္ကူ's vowel reached y −1341.

## 3. Anchor system

### 3.1 Anchor inventory

`top bottom stack side` on attachment targets, `_top _bottom _stack
_side` on the attaching marks. The studio's ⚓ mode can drag any of them;
a dragged position is stored in the project JSON and overrides the
formulas below verbatim.

### 3.2 Placement rules (exact)

With `x_min…x_max, y_min…y_max` the glyph's ink bounds,
`ink_w = x_max − x_min`, and

    mark_x       = x_min + ink_w · (0.75 if ink_w > 700 else 0.55)
    top_anchor_y = max(y_max + 60, 510)

All bounds are measured on the **unscaled reference drawing**, so every
weight master derives identical anchor coordinates: attachment heights
stay at the design position in every weight (the Bold pen bulges ±half
the extra stroke around the fixed spots, as in any fixed-anchor family)
and the masters interpolate cleanly. Horizontal side-chain gaps alone
grow with the pen (`pen_pad = 46·(scale−1)`, ~19 units at Bold) so the
*ink* gap — not just the anchor gap — meets the clearance protocol in
every weight.

(0.75/0.55 from Padauk: ကီ attaches at 0.73 of ink width, ကု at 0.78,
ခု at 0.56; the 60-unit clearance from Padauk's ကိ gap of 76):

| Role | Anchors |
| :--- | :--- |
| Base | `top (mark_x, top_anchor_y)` · `bottom (bottom_x, max(min(y_min,0),−50)−40)` · `stack (centre_x, max(min(y_min,0),−50)−40)` |
| Top mark | `_top (cx, y_min−20)` · `top (cx, y_max+20)` |
| Kinzi | `_top (cx, y_min−20)` · `top (x_max+225+pen_pad, y_min−20)` |
| Bottom mark | `_bottom (cx, y_max+20)` · `side (x_max, y_max+20)` · `_side (x_min−55−pen_pad, y_max+20)` |
| Stack mark | `_stack (cx, y_max+20)` · `side (x_max, y_max+20)` |
| Spacing sign | `top (mark_x, 510)` · `bottom (mark_x, max(min(y_min,0),−50)−40)`; the tall u/uu strokes instead put `bottom` BESIDE the bar at `(x_max+110+pen_pad, −115)` — a tone dot under ink that runs to −438 would overlap it (Padauk's ကျို့ dot sits right of the stroke) |
| u.wrapstroke | `_bottom (cx−183, −40)` — plants the bar on the wrap's under-sweep tail (base_x_max−48) with ink −236…−588, continuing ~150 units below the sweep so it reads as the tail descending (Padauk hangs its bar from a shallow frame; our wraps draw a deep sweep, so the bar extends it instead) · `side (x_max+55+pen_pad, −95)` for the tone dot of မြို့ |
| Medial ya | `side (x_max−30, −40)` · `top (cx, top_anchor_y)` |

`bottom_x` starts at `mark_x` and slides through candidate fractions
0.40–0.85 (step 0.025) to the nearest column band whose own ink stays
above −160 — the leg-avoidance scan that threads ည's below-marks between
its tail and descender. The scan never moves the *top* anchor.

Rules with a reason attached:

* **The −50 bottom/stack floor.** Below-marks and subjoined letters land
  in Padauk's −80…−478 band no matter how deep the base's own leg goes.
  Following န's leg down instead put န္န's stack at −890 — 290 units past
  the descender, into the next line.
* **Bottom marks carry `side`/`_side`, never a plain `bottom`.** Marks
  that follow a below-mark chain *beside* it, tops aligned, next ink 55
  units right (the 50-unit clearance protocol plus margin) — the
  geometry of Padauk's uni103D103E / uni103E102F ligatures. Chaining
  underneath is how ရွှံ့'s tone dot once reached −748.
* **Stack marks chain sideways too.** A medial after a subjoined form
  (က္ကွိ) lands beside the stack, not under it (was −814).
* **The kinzi's `top` anchor points right, at its own height.** A vowel
  stacked *on* the kinzi reached y 1345 — past usWinAscent, clipped on
  Windows and in browsers. Padauk ships fused kinzi+vowel glyphs with the
  added ink to the hook's right (သင်္ခံ: fused 1098…1466 vs bare
  1113…1301); the side anchor reproduces that geometry without artwork.
* **Spacing signs are mark bases with a fixed-height `top`.** In ကော် the
  asat sits on the ာ; in ကာံ the anusvara does. But the anchor does not
  follow the sign's ink: ါ is an 875-unit stem, and a mark above *that*
  lands at 1303. Padauk's fused ော် tops out at 856 — under the stem's
  top, crossing the stem.
* **U+25CC dotted circle carries full base anchors** so isolated marks
  attach to it, and U+1039 virama is synthesized empty (any sketched ink
  is discarded).

## 4. GSUB rule set (application order)

Rules are emitted only when every glyph they mention is drawn, before any
script statement, so they register under all three languagesystems. Full
generated source: `generate_features()` in `json_to_ufo.py`; the compiled
form is in any built font's GSUB.

| Feature | Lookup | Rule | Guard |
| :--- | :--- | :--- | :--- |
| rphf | — | င ် ္ → kinzi | — |
| blwf | — | ္ + C → C.sub | — |
| pres | ra_wide | ြ → ြ.wide before @WIDE_BASES | wide set **measured**: base may overhang the narrow wrap's ink by ≤100 units (Padauk's split: narrow ≤73, wide ≥136) |
| pres | ra_tall | ြ(.wide) → .tall(.wide) when ိ/ီ/ဲ follows the wrapped base | filtering set = the trigger vowels only, so ကြွီ goes tall across the ွ; **ံ is not a trigger** |
| pres | ya_tuck | ျ → ျ.beforewa before ွ/ှ | `lookupflag 0;` — lookupflag is STICKY across named lookups in one feature block; without the reset this inherits ra_tall's filtering set and ကျွ silently stops tucking |
| pres | wa_fuse | ွ + ှ → the traced `ွ.ha` hook | must run FIRST: it makes ကျွှ read as ja + one hook, and by consuming the ွ it keeps the wrap+wa fusion off ကြွှ — so မြွှေ stays plain-wrap + the small hook, as Padauk draws it |
| pres | ya_fuse | ျ.beforewa + ွ/ှ/ွ.ha → the traced `.wa`/`.ha`/`.waha` ligature | adjacent-pair GSUB4; the ligature then serves as the medial context for the tall-vowel rule (ကျွု) and carries ya's anchors |
| pres | ha_fuse | ှ + ု/ူ → the traced `ှ.u`/`ှ.uu` hook | must run LAST of the three: လျှု has to fuse ja+ha and keep its tall vowel (Padauk uni103B103E + uni102F), so the ja fusion consumes that ha first; only a ha with no ja before it pairs with the vowel (ရှု) |
| blws | desc_vowels | ု/ူ → tall .alt after subjoined forms | filtering set includes the `.sub` glyphs (context must SEE them — dropping them breaks စက္ကူ) plus the vowels |
| blws | medial_vowels | ု/ူ → tall .alt after ျ(.beforewa)/ွ | Padauk's ကျု မွု လျှု မွှူ: the vowel is the full-height straight stroke standing after the medial, never the curl. The rule fires straight through an intervening ha (ha is not in the filter); ရှု keeps the curl because there the ha follows a BASE, which is always visible and blocks the match |
| blws | side_bases | န/ည → .alt before below-marks *and* subjoined forms | per-base trigger lists; filtering set = triggers only, so the swap fires across an intervening asat (ကျွန်ုပ်) or top mark (နို့) |
| blws | side_bases_ra | ရ → .alt before ု/ူ | ra's own lookup filtering to u/uu only, so it fires ACROSS an intervening ha (ရှု = ra.alt in Padauk) — while ရွ ရှ themselves stay plain, Padauk's split; in the shared lookup the visible ha would block it |
| abvs | — | ိ + ံ → ိံ ligature | — |
| abvs | — | kinzi → kinzi.left before ျ | in base+kinzi+ya clusters (အင်္ကျီ) the vowel attaches to the YA — a base glyph, so the mark chain restarts and the vowel cannot chain beside the kinzi; the pre-shifted variant (synthesized, no artwork: same ink, `_top` 250 units right of centre) moves the kinzi out of the vowel's airspace, where Padauk's fused kinzi+vowel glyphs put it |
| psts | — | after a ြ wrap: ွ/ှ → `.small` in-wrap copies (second rule for a mark chained onto an already-small one, ကြွှ); ု → the fused wrap+u form in two steps (the wrap swaps to its traced `.u` variant in front of the ု, then the ု behind an already-fused wrap becomes the invisible zero-width `u.ghost`, which carries the side anchor for မြို့'s tone dot) — feaLib allows one marked run per rule, hence two rules; fonts without the traced forms fall back to the synthesized `u.wrapstroke` bar; ူ → the tall spacing .alt standing after the cluster (Padauk တြူ) | filtering set = the below-marks and their smalls |

GPOS (`mark`, `mkmk`) is generated by ufo2ft from the anchors of §3 —
there are no hand-written positioning rules.

## 5. Language handling

All rules register under `DFLT dflt` and `mym2 dflt` — not `mymr`,
whose shaper does no reordering (measured: with `mym2` masked off, ကေ
shapes to [ka, e] and the wrap of မြန်မာ stays behind its base). The
extension repertoires (Mon kinzi-on-anything, Shan ၸ-clusters, S'gaw
Karen tones) shape through the same defaults: their marks classify by
Unicode category and attach through the same anchor roles, which the
Block K corpus cases (shaped with `mnw`, `shn`, `ksw` language tags)
verify. There are currently **no per-language rule overrides**; when one
becomes necessary the extension point is a `language` statement inside
the feature block:

```fea
feature blws {
  script mym2;
    language dflt;
      # Burmese defaults …
    language MON;          # exclude_dflt to replace rather than extend
      # Mon-only substitutions …
} blws;
```

## 6. Collision detection and error handling

The build itself prevents the classical collisions by construction
(side-chaining, the −50 floor, leg avoidance). Verification is a separate
measurement pass — `pipeline/validate_spec.py` — that shapes two corpora
with HarfBuzz and checks every cluster: the synthetic specification
corpus (`pipeline/spec_corpus.txt`, 1 486 clusters, Blocks A–O) and the
real-vocabulary corpus (`pipeline/word_corpus.txt`, Block W: 711 genuine
words that together contain all 1 213 syllable clusters occurring in the
12 451-word Myanmar Wiktionary vocabulary):

| Check | Method | Severity |
| :--- | :--- | :--- |
| coverage | every character maps to a glyph | GAP (drawing to-do) |
| dotted-circle | U+25CC was not inserted | SPEC (malformed input) |
| virama | U+1039 consumed when the `.sub` exists | FAIL |
| kinzi | င်္ fused, no full-size င left | FAIL |
| reorder | ေ and ြ render before their base (per cluster) | FAIL |
| wrap | wrapped base starts inside the wrap; overhang ≤100 | FAIL / WARN |
| attachment | every mark repositioned by GPOS, lands within 220 units of a base | FAIL |
| clipped | no positioned ink outside usWinAscent/Descent | FAIL |
| bounds | ink outside the ±900/−600 design band | WARN |
| collision | pairwise mark ink: overlap = FAIL, gap < 50 = WARN | FAIL / WARN |
| advance | the cluster advances | FAIL |

The collision measurement flattens both outlines (8 segments per curve),
prunes by bounding box, then takes the true minimum segment-to-segment
distance — containment counts as overlap. Severities: **FAIL** = the
font is wrong; **WARN** = inside tolerance, worth a look; **GAP** =
glyph not drawn yet; **SPEC** = the test datum itself is malformed (the
font behaved correctly) — kept separate so a bad test case can never
mask a real bug.

```bash
cd pipeline
python3 validate_spec.py build-mgs/MyanmarGlyphSans-Regular.ttf
python3 validate_spec.py MyFont.ttf --reference ../web/fonts/Padauk-Regular.ttf --json report.json
```

The same pass runs in CI via `tests/test_spec_validation.py`: any
FAIL-severity finding against the shipped fonts fails the build.

## 7. ZWJ / ZWNJ

U+200C/200D need no glyphs and no rules: HarfBuzz renders
default-ignorables as invisible zero-width glyphs and applies its own
join-control logic before font rules run. Verified against Padauk: for
ZWNJ-interrupted stacks, ZWSP, and ZWNJ after a medial cluster, this
pipeline's output is glyph-for-glyph and advance-for-advance identical
to Padauk's (both engines show the dotted circle for the ill-formed
ZWNJ-before-virama sequence, and both erase ZWSP/ZWNJ to zero width
otherwise).
